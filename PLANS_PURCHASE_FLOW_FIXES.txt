PLANS PURCHASE FLOW FIXES
=========================

Date: 23 July 2026
Area: Authenticated Plans screen, purchase bottom sheet, and future-plan flow


OVERVIEW
--------

This update fixes three related UI and purchase-flow issues:

1. MiFi and Liberty Global prices in the purchase bottom sheet now include VAT.
2. A future-plan purchase now uses the active plan's end date consistently.
3. The two bottom-sheet button labels now use the same font weight as the
   "purchase now" button on the main Plans screen.


1. MIFI AND LIBERTY GLOBAL BOTTOM-SHEET PRICES
-----------------------------------------------

Problem
~~~~~~~

The main Plans screen showed VAT-inclusive prices, but the purchase bottom
sheet received only the base PlanAmount.

Examples:

- MiFi card: $90.00
- Previous MiFi bottom sheet: $81.82

- Liberty Global card: $21.00
- Previous Liberty Global bottom sheet: $19.09

Previous implementation
~~~~~~~~~~~~~~~~~~~~~~~

The plan models prepared for the bottom sheet used:

    price: plan.planAmount

This excluded the plan's VatAmount.

New implementation
~~~~~~~~~~~~~~~~~~

Both plan conversions now use:

    price: plan.planAmount + plan.vatAmount

As a result, the plan card and bottom sheet display the same total:

- MiFi: $90.00
- Liberty Global: $21.00

Affected file
~~~~~~~~~~~~~

lib/app/Plans/PlanScreen/view/home_plan_screen.dart

Affected methods:

- _toMifiPurchaseSheetPlan
- _toLibertyGlobalPurchaseSheetPlan


2. FUTURE-PLAN START DATE FLOW
------------------------------

Problem
~~~~~~~

The purchase bottom sheet displayed the active plan's end date in its warning.
For example:

    The future plan will start when the current plan ends on 17 Aug 2026.

However, after tapping "future plan", the confirmation screen used the selected
new plan's API StartDate instead. In the reported case, it showed:

    begins 21-06-19

That old 2019 date was also carried to payment and submitted to the purchase API
as Bundle.StartDate.

Therefore, the date promised in the bottom sheet and the date displayed and
submitted later in the flow did not match.

Previous date source
~~~~~~~~~~~~~~~~~~~~

The confirmation route arguments were populated from:

    selectedApiPlan.startDate

For the MiFi alternate-contact path,
MifiAltContactArgsBuilder also re-read:

    selectedApiPlan.startDate

New date source
~~~~~~~~~~~~~~~

The flow now obtains the date from:

    plansState.earliestAddOnsPrimaryPlan?.endDateTime

This is the same active-plan end date already used to build the bottom-sheet
warning.

The date is converted to an ISO-8601 string once when the purchase sheet opens:

    activePlanEndDate?.toIso8601String()

That value is then carried through the route instead of being replaced by the
new plan's StartDate.

New future-plan flow
~~~~~~~~~~~~~~~~~~~~

1. The purchase sheet reads the active plan's EndDate.
2. The warning displays that date, for example "17 Aug 2026".
3. Tapping "future plan" sets forceNow to false.
4. The same date is passed as futurePlanStartDate.
5. If MiFi requires the alternate-contact screen, the new route argument keeps
   the date across that screen.
6. The confirmation screen receives the same date and displays it in its
   existing DD-MM-YY format, for example "begins 17-08-26".
7. The payment flow parses and forwards the date.
8. The existing change-bundle request builder submits it as Bundle.StartDate,
   formatted as "yyyy-MM-dd HH:mm".

Activate-now behavior
~~~~~~~~~~~~~~~~~~~~~

The "activate now" path passes an empty futurePlanStartDate and keeps
forceNow set to true.

Therefore:

- Confirmation continues to show "begins immediately".
- The request continues to send ForceNow: true.
- Bundle.StartDate is not added to an activate-now request.

Paths covered
~~~~~~~~~~~~~

- MiFi with an alternate contact number already on the account.
- MiFi that must visit the alternate-contact screen first.
- Other plans using the shared future-plan confirmation route, including
  Liberty Global.

Affected files
~~~~~~~~~~~~~~

lib/app/Plans/PlanScreen/widgets/home_plan_purchase_sheet_launcher.dart

- Reads and serializes the active plan's end date.
- Passes futurePlanStartDate through future-plan callbacks.
- Passes an empty value through activate-now callbacks.
- Sends the date to either confirmation or the MiFi alternate-contact route.
- Stops using selectedApiPlan.startDate as the confirmation date.

lib/app/Plans/mifiAltContact/model/mifi_alt_contact_route_args.dart

- Adds the futurePlanStartDate route field.
- Adds the field to the constructor.
- Adds the field to Equatable props.

lib/app/Plans/mifiAltContact/view/mifi_alt_contact_args_builder.dart

- Previously copied selectedApiPlan.startDate into confirmation arguments.
- Now forwards routeArgs.futurePlanStartDate without replacing it.

Existing downstream files that consume the corrected value
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

These files did not need modification, but they explain how the corrected date
reaches the API:

lib/app/Plans/homePlanConfirmation/bloc/home_plan_confirmation_bloc.dart

- Parses futurePlanStartDate into selectedBeginDate.

lib/app/Plans/homePlanConfirmation/repository/home_plan_confirmation_repository.dart

- Formats the date for the "begins DD-MM-YY" confirmation text.

lib/app/Plans/homePlanConfirmation/view/home_plan_confirmation_screen.dart

- Passes selectedBeginDate into the payment-method route.

lib/app/common/services/payments/change_bundle_request_factory.dart

- When ForceNow is false, formats selectedBeginDate and writes it to
  Bundle.StartDate.


3. BOTTOM-SHEET BUTTON FONT WEIGHT
----------------------------------

Problem
~~~~~~~

The main plan-card "purchase now" label used FontWeight.w700, while the
bottom-sheet "future plan" and "activate now" labels used FontWeight.w400.

This made the bottom-sheet actions appear visually lighter and inconsistent
with the main purchase action.

Previous implementation
~~~~~~~~~~~~~~~~~~~~~~~

    bottomSheetPrimaryActionDualStyle.fontWeight = FontWeight.w400
    bottomSheetSecondaryActionDualStyle.fontWeight = FontWeight.w400

New implementation
~~~~~~~~~~~~~~~~~~

    bottomSheetPrimaryActionDualStyle.fontWeight = FontWeight.w700
    bottomSheetSecondaryActionDualStyle.fontWeight = FontWeight.w700

Both bottom-sheet button labels now match:

    planCardPurchaseNowTextStyle.fontWeight = FontWeight.w700

Only the font weight was changed. Existing font sizes, colors, button
backgrounds, dimensions, and callbacks remain unchanged.

Affected file
~~~~~~~~~~~~~

lib/app/Plans/PlanScreen/theme/theme.dart

Affected styles:

- bottomSheetPrimaryActionDualStyle
- bottomSheetSecondaryActionDualStyle
