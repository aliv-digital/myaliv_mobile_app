3. Task-by-task findings

RESET PASSWORD

- Source row / Ref ID: Source row 14
- Requirement: When the password does not meet the criteria, show exactly "Password must be 4 characters long".
- Current behavior: Submit validates a trimmed password as at least 8 characters with at least one ASCII letter and one number. Failure shows "use at least 8 characters, including a letter and a number" through AppUtils.showWarningToast, a bottom yellow Fluttertoast. The same 8-character guidance is permanently displayed below the fields. CreatePasswordState uses the same 8-character/letter/number rule when deriving canSubmit.
- Status: MISMATCH
- Relevant files: lib/app/Aliv-Mobile/createPassword/bloc/create_password_bloc.dart:44-55; lib/app/Aliv-Mobile/createPassword/bloc/create_password_state.dart:29-33; lib/app/Aliv-Mobile/createPassword/view/create_password_page.dart:149-154; lib/core/utils/appUtils.dart:41-48
- Smallest required change: In the existing CreatePasswordBloc/State, replace the current 8-character letter/number predicate with the literal source-sheet rule of exactly 4 trimmed characters and use the required message in the existing warning-toast presentation. Update the always-visible helper copy in create_password_page.dart so it does not contradict the validation. Preserve confirmation-mismatch and repository behavior.
- Blocker/dependency: The purple requirement directly supersedes the 8-character letter/number rule implemented in report 02. Frontend intent is clear, but the Kansys password policy was not inspected and may reject a 4-character password; backend compatibility should be confirmed before implementation verification.

ALIVFIBR PORTAL FAILURE

- Source row / Ref ID: Source row 139 / AUTH-010
- Requirement: If the ALIVFibr portal link fails, show "we couldn't open the ALIVFibr portal. try again or visit portal.alivfibr.com." with a retry action in a Banner.
- Current behavior: ALIVFibr calls launchUrl for https://portal.alivfibr.com/myfibr/login.aspx in external-application mode. A false result displays the top error AppToast "Could not open ALIVfbr portal." There is no retry action, no Banner, and no local catch for a launchUrl exception.
- Status: MISMATCH
- Relevant files: lib/app/welcome/view/welcome_view.dart:52-53,158-179; lib/resources/widgets/top_toast.dart:9-112
- Smallest required change: Change only welcome_view.dart: keep the existing URI and launchUrl call, but route false results and launch exceptions to ScaffoldMessenger.showMaterialBanner using the exact required copy and a retry TextButton that repeats the same launch operation. Hide the banner after a successful retry. The existing MaterialBanner/retry pattern in create_password_page.dart:71-92 can be followed without adding a component or abstraction.
- Blocker/dependency: None. The failure signal already exists locally; exception handling should cover launchUrl failures that do not return false.

4. Regression risks

- Reset Password: changing from the report-02 rule to exactly four characters can create a frontend/backend policy mismatch and intentionally reverses the previous visible helper text and canSubmit criteria. Confirmation mismatch and save-failure handling must remain unchanged.
- ALIVFibr: retry must reuse the same fixed URI and external launch mode, avoid stacking multiple banners, catch thrown launch failures, and check context.mounted after asynchronous attempts.
- OTP: adding inline copy without suppressing the current toast would duplicate the message. Only empty/incomplete local validation should move inline; invalid, expired, network, resend, and missing-context presentations must remain unchanged. Six-cell paste/autofill and red error borders must not regress.
- Existing uncommitted Authentication work from report 02 must be preserved; implementation should touch only the lines needed for these three purple tasks.
