2. Current flow summary

- Splash checks the persisted JWT refresh expiry. A valid session redirects to Home; otherwise the user reaches the service-selection screen.
- Selecting ALIV Mobile checks the same persisted session and routes to Home or Login. ALIV Mobile Guest and ALIVFibr are separate paths and were not audited further.
- Login validates required phone/password values and the Bahamas number locally, checks connectivity, then calls POST /v1/MyAliv/Auth/login. A direct JWT response completes authentication; an mfa_token response opens the six-digit Verification Code screen.
- OTP verify calls POST /v1/MyAliv/Auth/2fa/verify, persists the returned session, loads account/device context, and redirects to Home. Resend calls /Auth/2fa/resend.
- Forgot Password opens Verify Your Number, calls POST /v1/MyAliv/Auth/forgot, then reuses the Login OTP screen and verifier. After verification it attempts to route through Home to Create Password. Create Password calls POST /v1/MyAliv/Auth/update-password and redirects to Home on success.
- Face ID and Fingerprint are visible on Login but their buttons do nothing. A separate biometric lock implementation exists at the Home-route boundary.

4. Issues found

Login
- Invalid phone feedback can be duplicated and begins while the number is merely incomplete.
- Unknown API/Dio/parse errors are exposed as raw top-toast text.
- Session is saved before post-login account/device completion; a displayed login failure can still leave a persisted valid session.
- Direct login does not set the biometric session flag, producing behavior different from OTP login.
- Bahamas seven-digit acceptance versus the ten-digit design hint requires confirmation.

OTP
- One hard-coded header is reused for login and password reset and claims both email and SMS without inspecting delivery data.
- Invalid/expired/throttled OTP messages are not robustly categorized; raw backend copy can surface.
- Resend has no countdown/cooldown or attempt control.
- Six-digit/new endpoint assumptions conflict with the legacy api_catalog.json entry and require Kansys confirmation.

Forgot Password
- Verify Your Number does not reuse LoginPhoneNumberHelper; any non-empty digit sequence is sent.
- No local connectivity check or field-level invalid state exists.
- Forgot verification assumes the login 2FA endpoint returns a full JWT/session for a forgot token.
- Successful reset OTP navigates through Home before Create Password.

Create Password
- canSubmit omits the 64-character maximum and does not control button enablement.
- Visible letters/numbers guidance is not enforced.
- Local validation uses a bottom yellow Fluttertoast while other authentication errors use the shared top overlay toast; field error presentation is absent.

Biometrics
- Login Face ID and Fingerprint controls are nonfunctional placeholders and always visible.
- Existing biometric service/lock logic is not connected to Login.
- Home guard ignores isBiometricEnabled and has no configured failure fallback.

5. Shared/reusable logic discovered

- LoginPhoneNumberHelper: country-aware normalization/validation and API username construction. It should be reused by Verify Your Number once the approved Bahamas input rule is confirmed.
- BahamasPhoneInputFormatter: shared Login/Forgot presentation formatter, capped at ten digits.
- CustomCountryPhoneInputRow: shared phone/country input presentation.
- AuthCompletionService: shared direct-login and OTP post-token completion; needs transactional cleanup/rollback behavior before reuse is considered safe.
- LoginResponseParser: handles direct JWT and MFA challenge response shapes, including legacy key aliases.
- LoginOtpRepository/API client/JSON validator: reusable OTP verify/resend transport and response validation.
- AppToast: shared three-second top success/error overlay. Create Password local validation instead uses AppUtils bottom Fluttertoast.
- FingerFaceSecurityCubit/BiometricAuthService/BiometricLockScreen: existing device capability, local-auth, state-message, and retry logic that could support Login biometrics.
- DefaultButton: shared loading-disable behavior; current Create Password caller does not use validation state to disable it.

7. Open questions / spec conflicts

- The referenced Authentication design/message spec was not available in the workspace. Exact capitalization, punctuation, trigger timing, inline-versus-toast presentation, biometric visibility, and success copy cannot be conclusively approved.
- api_catalog.json documents legacy POST /Auth/two-factor-auth with Key/PinCode and /two-factor-auth/resend, while current code uses /Auth/2fa/verify with mfa_token/otp_code/Channel and /Auth/2fa/resend with mfa_token. Which is the active Kansys contract?
- Does Kansys always issue six-digit codes for both login and forgot-password flows? The code says six; the local catalog is legacy and does not confirm length.
- Does /Auth/forgot deliver to SMS, email, or both, and should the UI show a masked phone/email? Current UI always claims both.
- Is a seven-digit Bahamas subscriber number valid input, or must users enter the full 242 + seven-digit number shown by the UI?
- What are the complete Kansys error codes/messages for invalid number, wrong credentials, lockout duration, invalid/expired OTP, resend throttling, unknown account, and password-policy rejection?
- Does a forgot-password mfa_token verify through /Auth/2fa/verify and return a normal JWT session, or is a reset-specific verification token/endpoint required?
- Should successful reset OTP authenticate the user, or only authorize password reset? Current flow creates a full session and loads account/device data before password creation.
- Should Create Password enforce only length, require at least one letter or number, restrict to alphanumeric characters, or apply a stronger Kansys policy?
- Should Login show only the biometric type available/enabled for the device, and must a valid cached JWT exist before Face ID/Fingerprint can sign in?
- Should biometric cancellation return to Login without an error, and what fallback is required after lockout/unavailable hardware?
