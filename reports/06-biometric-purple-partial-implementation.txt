6. Cancellation/setup handling preserved

- userCanceled and userRequestedFallback now map to BiometricAuthResult.canceled instead of failed.
- Login treats cancellation/fallback as a silent return to password login: no non-match or lockout toast is shown.
- Login biometric buttons are enabled only when the existing saved biometric-enabled state is true and the corresponding availability flag is true.
- Buttons are disabled while authentication is in progress, and remain disabled for unavailable/not-enrolled or disabled biometric methods.
- A runtime unavailable/not-enrolled result or unexpected platform error does not display any of the three purple messages.
- The shared cubit retains its previous generic cancellation message for existing Home behavior; Login ignores that shared message and performs its own result-specific mapping.

9. Regression risks

- local_auth controls when a non-match is returned versus when its OS prompt continues collecting attempts; the app maps only the final false result.
- The existing repository treats BiometricType.strong as fingerprint availability. That pre-existing platform ambiguity was not redesigned in this scoped task.
- Login relies on the biometric status loaded at startup or subsequently updated by the existing cubit; external device-enrollment changes while the app is running may require the existing status reload path.
- Changes to the shared result enum could affect exhaustive downstream switches; targeted analysis found no compile errors, and existing switches retain their prior visible fallback behavior.

11. Exact cases ready for verification

- Fingerprint reports temporaryLockout: top error toast shows exactly "Too many failed attempts. Please log in with your password."
- Fingerprint reports biometricLockout: the same exact lockout toast is shown.
- Face ID lockout: no Face-not-detected message and no fingerprint-lockout message is shown.

- Runtime unavailable/not-enrolled or unexpected error: no purple failure message is shown.
- Local biometric success: Login remains on the current screen, shows no "Welcome!", performs no Home navigation, and changes no MyAliv/Kansys session state.
- Password login remains fully usable after biometric non-match, cancellation, lockout, or other biometric outcomes.
