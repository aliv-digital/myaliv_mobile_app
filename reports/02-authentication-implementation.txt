3. Implemented requirements

Login
- Empty mobile on submit now displays inline: "enter your mobile number".
- Invalid mobile now displays inline: "enter a valid 10-digit mobile number".
- Bahamas mobile validation now requires exactly ten digits beginning with 242; the previous seven-digit auto-prefix path was removed. Unsupported non-formatting characters are rejected by the shared validator.
- Phone validation is submit-driven and shown only below the phone field; the duplicate message below Password was removed.
- Empty password on submit now displays inline: "enter your password".
- Existing reliable FailedUsernameOrPassword mapping now displays: "Invalid login credentials."
- Existing reliable FailedUsernameIsLocked mapping now displays: "Invalid credentials. Reset your password?"
- Existing reliable FailedSimpleValidation mapping now uses the approved inline mobile-format message.

OTP / Verification Code
- Verification connectivity precheck and structured no-internet/timeout errors now display: "We couldn't verify the OTP due to a network error. Please try again later."
- Existing structured unauthorized/invalid-OTP cases and explicit invalid-OTP/two-factor messages now display: "Invalid OTP."
- Structured expired-OTP errors and backend text explicitly identifying an expired OTP/code now display: "OTP expired."
- "change phone number" now opens the required confirmation modal:
  - Title: "change your number?"
  - Body: "you'll need to start again with your new number. your current code will stop working."
  - Actions: "change number" / "cancel"
- Confirming change number returns to the preceding Login or Verify Your Number screen; cancel keeps the current OTP active.

Forgot / Reset Password
- Verify Your Number now reuses LoginPhoneNumberHelper.
- Empty mobile displays inline: "enter your mobile number".
- Invalid mobile displays inline: "enter a valid 10-digit mobile number".
- Local phone validation no longer produces a duplicate top toast.
- Successful /Auth/forgot response now shows toast: "a verification code has been sent to your number and email" before opening OTP.
- Terms copy now reads: "by pressing the 'send' button you agree to our terms & conditions and privacy policy" while preserving the two existing links.

Create Password
- Screen copy now reads: "create password — set a new password for your account so you can sign in and access the myALIV app".
- Password validation now requires at least eight characters, at least one ASCII letter, and at least one number.
- The previous app-side 64-character maximum was removed because it is not an authoritative requirement for this task.
- Password rule/helper message is: "use at least 8 characters, including a letter and a number".
- Confirmation mismatch displays: "these passwords don't match. re-enter them to continue."
- Server-side save failure now displays a Material banner: "we couldn't save your new password. try again in a few moments." with a "retry" action.
- Success toast now displays: "Password reset successful!"

- Three consecutive incorrect OTPs: no reliable backend identifier or attempt-count field is present. The requested banner/resend action was not added; no client-side security counter was invented.
- Password reuse: no reliable response identifier dedicated to reuse is present. The approved reuse copy was not mapped; failures use the approved generic save-failure banner.
- Unknown login failures: only the existing exact identifiers FailedSimpleValidation, FailedUsernameIsLocked, and FailedUsernameOrPassword were changed. Other backend/Dio text remains unmapped pending a Kansys error-code contract.
- Unknown OTP failures: only structured network/unauthorized/invalid/expired categories and text explicitly identifying invalid/expired OTP are normalized. Other server text remains unmapped rather than guessing.
