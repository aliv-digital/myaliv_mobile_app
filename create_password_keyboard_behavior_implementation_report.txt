Exact behavior implemented
--------------------------

- PasswordInput now accepts optional TextInputAction? textInputAction and
  ValueChanged<String>? onSubmitted parameters and forwards both directly to
  its existing internal TextField.
- The existing private FocusNode, focus listener, focus-border state, and
  disposal lifecycle are unchanged.
- The first password field uses TextInputAction.next. Flutter's normal focus
  traversal moves focus to the re-enter-password field; no manual nextFocus
  call or raw keyboard listener was added.
- The re-enter-password field uses TextInputAction.done. Pressing Done invokes
  the screen's existing SubmitCreatePassword event path.


Shared Continue/Done action
---------------------------

One screen-local submit callback reads CreatePasswordBloc and dispatches
const SubmitCreatePassword(). The same callback is supplied to both the
Continue button's onPressed and the second field's onSubmitted. The submitted
String parameter is ignored. No canSubmit gate, validation logic, or business
logic was added to the screen.


Duplicate-submit protection
---------------------------

At every invocation, the shared callback reads the current
CreatePasswordBloc state. If the current status is
CreatePasswordStatus.submitting, it returns without dispatching another
event. This gives keyboard Done the same in-flight protection as the loading
Continue button.
